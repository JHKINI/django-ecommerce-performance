# 상품 목록 API 성능 개선 실험

## 1. 실험 목적

대량의 상품 데이터를 조회할 때 발생하는 API 응답 지연과 응답 데이터 크기를 측정하고, 페이지네이션 적용 전후의 차이를 비교한다.

## 2. 실험 환경

- Framework: Django REST Framework
- Database: PostgreSQL
- Test data: 상품 데이터 100,000건
- Pagination: PageNumberPagination
- Page size: 50건
- Measurement: 각 조건별 5회 측정
- Server: Django 개발 서버

## 3. 성능 측정 결과

| 측정 항목 | 페이지네이션 미적용 | 페이지네이션 적용 |
|---|---:|---:|
| 평균 응답 시간 | 7,387.40ms | 278.34ms |
| 중앙값 응답 시간 | 7,469.05ms | 284.14ms |
| 평균 응답 크기 | 11,883.72KB | 6.09KB |
| 응답 상품 수 | 100,000건 | 페이지당 50건 |

## 4. 개선 결과

- 평균 응답 시간 약 96.2% 감소
- 평균 응답 크기 약 99.95% 감소
- 페이지 단위로 상품 데이터를 조회하도록 개선
- 전체 데이터 개수와 다음 페이지 링크 제공
- 1페이지와 2페이지 사이의 상품 ID 중복 여부 검증

## 5. 기능 검증

- 전체 상품 개수 100,000건 확인
- 페이지당 상품 수 50건 확인
- 다음 페이지 및 이전 페이지 링크 확인
- 1페이지와 2페이지 간 상품 ID 중복 0건 확인

## 6. 결과 해석 및 한계

페이지네이션 적용 후 한 번의 요청에서 처리하는 데이터와 응답 크기가 감소했으며, 측정 환경에서 평균 응답 시간이 단축되었다.

단, 페이지네이션 적용 전후에는 한 번에 반환하는 상품 수가 다르므로, 이 결과를 동일한 데이터량을 처리하는 순수 연산 성능 비교로 해석해서는 안 된다.

또한 측정은 Django 개발 서버에서 각 조건별 5회 수행했다. 운영 환경의 성능을 보장하는 결과는 아니며, 동시 사용자 부하 테스트와 추가 반복 측정이 필요하다.
